Apache Superset 项目架构

Superset 是一个数据探索与可视化平台:Flask/Python 后端负责元数据、权限、查询编排,React/TypeScript 单页应用负责图表编辑、仪表盘和 SQL Lab,Celery 承担异步与定时任务。本文按当前检出的代码梳理,所有路径均可在仓库中找到。

基于 master @ c0a86c7596 · 版本号 0.0.0-dev(Helm appVersion 6.1.0)· 整理于 2026-11-12

概览与技术栈

后端

Python ≥ 3.11 · Flask · Flask-AppBuilder 5 · SQLAlchemy 2.0 · Celery 5.6 · pandas 3.1 · sqlglot 30 · marshmallow · pydantic 2 · gunicorn

前端

Node 24 · React 18.3 · TypeScript 7.0 · antd 6 · Emotion 11 · Redux Toolkit 1.9 · react-router 5 · webpack 5 + swc · ECharts / deck.gl / AG Grid

基础设施

元数据库(PostgreSQL / MySQL / SQLite)· Redis(broker、缓存、pub/sub)· Docker 多阶段镜像 · Helm chart · Node 版 WebSocket 服务

质量工具

pytest · Jest 30 + React Testing Library · Playwright · ruff / mypy / pylint · oxlint / oxfmt / stylelint · pre-commit

整体是一个「服务端渲染外壳 + SPA」的结构:Flask 渲染 spa.html 并把 bootstrap 数据写进 DOM,前端接管路由后只通过 /api/v1/* REST 接口与后端交互。

后端架构

应用启动

  1. 工厂函数 — superset/app.py 的 create_app() 创建 SupersetApp,从 SUPERSET_CONFIG(默认 superset.config)加载配置。
  2. 初始化器 — superset/initialization/__init__.py 的 SupersetAppInitializer.init_app() 依次完成密钥检查、会话、特性开关、数据库与迁移、Celery、CSRF、缓存、sqlglot 方言注册。
  3. 应用上下文内 — init_app_in_ctx() 配置 Flask-AppBuilder 与安全管理器,注册数据源类型,再由 init_views() 注册约 40 个 REST API 和各页面外壳视图。
  4. 依赖注入与扩展 — init_core_dependencies() 把具体实现注入 superset-core;init_extensions() 发现并加载 .supx 扩展包。
  5. WSGI 中间件 — 外层包裹扩展缓存、应用根路径、旧版 /superset/* 路径 308 重定向。

全局单例(db、appbuilder、cache_manager、celery_app、security_manager、feature_flag_manager 等)集中定义在 superset/extensions/__init__.py。

配置与特性开关

  • 配置覆盖顺序:superset/config.py 默认值 → SUPERSET_CONFIG_PATH 指向的文件,或 PYTHONPATH 上的 superset_config 模块 → SUPERSET__SQLALCHEMY_DATABASE_URI 等环境变量。
  • 特性开关:DEFAULT_FEATURE_FLAGS 与 FEATURE_FLAGS 合并,可用 GET_FEATURE_FLAGS_FUNC 动态决定;前端通过 bootstrap 数据拿到同一份开关。
  • 默认开启:SOFT_DELETE、VERSION_HISTORY、TAGGING_SYSTEM。默认关闭:ENABLE_EXTENSIONS、SEMANTIC_LAYERS、GLOBAL_TASK_FRAMEWORK、GLOBAL_ASYNC_QUERIES、ALERT_REPORTS、THUMBNAILS、EMBEDDED_SUPERSET。

核心数据流

图表取数

  1. 前端构造查询 — src/components/Chart/chartAction.ts 取插件注册的 buildQuery 生成 QueryContext,POST 到 /api/v1/chart/data。
  2. 反序列化 — ChartDataRestApi(superset/charts/data/api.py)用 ChartDataQueryContextSchema 和 QueryContextFactory 把请求变成 QueryContext + 若干 QueryObject。
  3. 鉴权 — ChartDataCommand.validate() 调 query_context.raise_for_access() 做对象级权限检查。
  4. 查缓存 — QueryContextProcessor 经 QueryCacheManager 查 data_cache,命中则直接返回。
  5. 生成 SQL — 数据源的 ExploreMixin.get_sqla_query()(superset/models/helpers.py)拼出 SQLAlchemy 查询,注入行级安全条件并渲染 Jinja 模板。
  6. 执行 — Database.get_df()(superset/models/core.py)经 get_sqla_engine() 连接目标库,方言差异由 db_engine_specs/ 中对应的 BaseEngineSpec 子类处理。
  7. 后处理 — QueryObject.exec_post_processing() 用 pandas 做透视、滚动、同环比等运算,结果写入缓存并返回。

语义视图走另一条支路:superset/semantic_layers/mapper.py 把 QueryObject 映射成 SemanticQuery 交给语义层实现执行。

SQL Lab 执行

  1. 入口 — POST /api/v1/sqllab/execute/,SqlLabRestApi 组装 ExecuteSqlCommand(superset/commands/sql_lab/execute.py)。
  2. 准备 — 权限校验、Jinja 渲染,superset/sql/parse.py(基于 sqlglot)拆分语句、提取表名、按需注入 RLS。
  3. 同步或异步 — 同步执行器在 Web 进程内直接跑;异步执行器把 sql_lab.get_sql_results 任务投给 Celery,要求已配置 RESULTS_BACKEND。
  4. 结果 — worker 执行后把结果序列化(msgpack/Arrow)压缩写入结果后端;前端轮询查询状态,再从 /api/v1/sqllab/results/ 取回。

后台任务

能力链路

安全模型

权威说明在仓库根目录的 SECURITY.md。实现集中在 superset/security/manager.py 的 SupersetSecurityManager,可通过 CUSTOM_SECURITY_MANAGER 替换为其子类。

层次机制
角色内置 Admin、Alpha、Gamma、sql_lab、Public,由 sync_role_definitions() 根据权限-视图组合生成
路由级REST API 用 @protect(),旧视图用 @has_access_api / @has_access
对象级数据类资源(仪表盘、图表、数据集、查询、库表)调 security_manager.raise_for_access(...);其他资源靠路由鉴权加 DAO base_filter
行级安全 RLSRowLevelSecurityFilter 模型;图表查询在生成 SQL 时注入,SQL Lab 中由 sqlglot 转换器改写(需 RLS_IN_SQLLAB)
嵌入访问POST /api/v1/security/guest_token/ 签发 guest token,携带可访问资源与附加 RLS;嵌入页只接受 allowed_domains 内的来源
API key带 scope 的 API key(superset/security/api_key_scopes.py),由 FAB_API_KEY_ENABLED 控制

前端架构

构建与入口

  • webpack 5 + swc-loader 转译,产物输出到 superset/static/assets,同时生成 manifest.json 供 Flask 模板引用。webpack 内不做类型检查,类型检查由 npm run type 单独执行。
  • 入口:spa(src/views/index.tsx)、embedded(src/embedded/index.tsx)、menu(服务端渲染页面用的独立菜单)、service-worker;每个入口先执行 src/preamble.ts。
  • 开发服务器监听 9000 端口,webpack.proxy-config.js 把请求代理到 8088 的 Flask,并改写返回 HTML 中的资源引用。

应用外壳

  1. Bootstrap 数据 — Flask 把用户、配置、特性开关写入 #app 的 data-bootstrap 属性,src/utils/getBootstrapData.ts 解析并缓存。
  2. Preamble — 初始化 SupersetClient、特性开关、语言包、配色与格式化器。
  3. App — src/views/App.tsx 注册图表插件,用 RootContextProviders 包裹主题、Redux、拖拽等上下文,渲染菜单与路由。
  4. 路由 — src/views/routes.tsx 定义约 40 条路由,页面组件在 src/pages/,除首页外全部懒加载。

状态管理

单一 Redux store(src/views/store.ts,Redux Toolkit)。主要 slice:charts、explore、sqlLab、dashboardInfo、dashboardState、dashboardLayout(redux-undo 支持撤销)、nativeFilters、dataMask、datasources。SQL Lab 的库表元数据等读取走 RTK Query(src/hooks/apiResources/queryApi.ts)。

图表插件系统

  1. 定义 — 每个图表是一个 ChartPlugin,提供五样东西:metadata、controlPanel(Explore 控件)、buildQuery(表单 → 查询)、transformProps(结果 → 组件 props)、Chart(渲染组件)。
  2. 注册 — src/setup/setupPlugins.ts 执行 new MainPreset().register(),把上述五项写入 @superset-ui/core 的五个单例注册表。
  3. 编辑 — Explore 按图表类型从注册表取 controlPanel 渲染控件,用户修改产生 form data。
  4. 渲染 — Chart.tsx → ChartRenderer → SuperChart,按需懒加载插件的组件与 transformProps 代码块。

仪表盘

  • 组件链:pages/Dashboard → DashboardPage(数据注入)→ DashboardBuilder → DashboardGrid。
  • 布局是一个扁平的组件字典(ROOT、GRID、ROW、COLUMN、TABS、CHART、MARKDOWN 等),渲染器在 dashboard/components/gridComponents/,拖拽用 react-dnd。
  • 原生筛选器和交叉筛选的取值统一存入 dataMask,由 getFormDataWithExtraFilters.ts 合并进每个图表的查询。

主题与国际化

  • antd 6 组件统一从 @superset-ui/core/components 引入;主题基于 antd design token,由 @apache-superset/core/theme 和 src/theme/ThemeController.ts 管理,样式用 Emotion。
  • 翻译函数 t() 来自 @apache-superset/core/translation;词条是 superset/translations/<lang>/LC_MESSAGES/messages.po,构建时转成 JSON 语言包。
  • 自定义 lint 规则会检查硬编码颜色和未包 t() 的文案。

扩展体系

这部分是近期新增的架构,目标是让第三方在不改主仓库的前提下扩展前后端。

易踩的坑

以下几点与旧版本 Superset 或常见印象不同,读代码和查资料时容易混淆:

  • antd 是 v6,TypeScript 是 7.0,React 是 18.3,但 react-router 仍是 v5。
  • 前端不再使用 ESLint 和 Prettier,改为 oxlint 和 oxfmt。Cypress 已移除。
  • legacy-plugin-* 系列图表包已不存在,老图表已并入 plugin-chart-* 或删除。
  • superset/async_events/ 已不存在,异步图表查询改建在全局任务框架之上。
  • 旧的 /superset/* 路径由中间件 308 重定向到新路径。
  • 软删除和版本历史默认开启:ORM 查询会被全局监听器自动加上软删除过滤条件。
  • superset/tables/、columns/、embedded_dashboard/ 是只剩许可证头的空壳目录。
  • 仓库里有两个 superset-core:根目录的是 Python 包,superset-frontend/packages/ 下的是 npm 包。
核实范围:本文依据对源码文件的阅读整理,没有运行构建或测试。CI 工作流的用途按文件名归纳,未逐个核对步骤;get_sqla_query、Database.get_df 等长函数只读了调用关系,未通读实现;前端在轮询与 WebSocket 之间如何选择未确认。
